# بیدل — نسخه ارتقایافته

بیدل یک بازی آنلاین چهار نفره Hearts با SSE، بازی فوری با ربات، امتیازشمار پاسور واقعی، پروفایل، رتبه‌بندی و چت اتاق است.

## اجرا

```bash
npm install
npm start
```

بدون `DATABASE_URL` سرور اجرا می‌شود، اما آمار و پروفایل فقط در حافظه همان اجرای سرور هستند و دائمی محسوب نمی‌شوند.

## PostgreSQL

برای فعال شدن ذخیره دائمی:

1. یک PostgreSQL بسازید.
2. مقدار `DATABASE_URL` را در محیط اجرای SnapDeploy قرار دهید.
3. برنامه را Deploy/Restart کنید.
4. سرور در اولین اجرا جدول‌های `bidel_players` و `bidel_events` را خودکار می‌سازد.

در صورت وجود `bidel-stats.json` قدیمی و فعال بودن دیتابیس، آمار قدیمی به‌صورت best-effort مهاجرت می‌شود. چون نسخه قدیمی آمار را با نام ذخیره می‌کرد، اتصال قطعی آن رکوردها به شناسه‌های جدید بازیکنان ممکن نیست؛ برای همین رکوردهای مهاجرتی با شناسه legacy نگهداری می‌شوند.

## قوانین ثبت آمار

- فقط بازی کامل انسانی چهار نفره ثبت می‌شود.
- حضور حتی یک ربات در طول بازی، کل بازی را از آمار حذف می‌کند.
- پایان توافقی ثبت نمی‌شود.
- بازی ناقص ثبت نمی‌شود.
- ثبت نتیجه با `event_id` یکتا و تراکنش PostgreSQL idempotent است.
- نتیجه بازی آنلاین در سرور محاسبه و ثبت می‌شود؛ مرورگر نتیجه آنلاین را به سرور تحمیل نمی‌کند.
- نتایج امتیازشمار فیزیکی خوداظهاری هستند و در رتبه‌بندی آنلاین محاسبه نمی‌شوند.
- شناسه داخلی بازیکن در آمار عمومی نمایش داده نمی‌شود؛ خروجی عمومی از شناسه نمایشی مستقل استفاده می‌کند.
- ورود، فرمان‌های بازی و صدور مجوز SSE به توکن پروفایل نیاز دارند؛ مجوز SSE کوتاه‌عمر است.
- اگر بازیکن در نوبت خود ۴۵ ثانیه اقدامی نکند، اولین کارت مجاز به‌صورت خودکار بازی می‌شود.

## استقرار روی SnapDeploy

- Repository را در GitHub قرار دهید.
- سرویس Node.js را به Repository وصل کنید.
- Build/Install: `npm install`
- Start: `npm start`
- Environment: `DATABASE_URL` و `SESSION_SECRET` (ثابت و محرمانه)، و در صورت نیاز `TRUST_PROXY=1` و `TURN_TIMEOUT_MS`
- بعد از Deploy، `/api/health` باید `ok:true` و وضعیت دیتابیس را همراه با تعداد اتاق‌ها، بازیکنان، اتصال‌های SSE و uptime برگرداند.

## PWA

Service Worker فقط shell صفحات را cache می‌کند و API/SSE را cache نمی‌کند. برای هر نسخه جدید `CACHE_NAME` در `sw.js` افزایش داده می‌شود.

## آزمون خودکار

```bash
npm test
npm run check
```

`tests/sim.js` سرور آزمایشی را اجرا می‌کند و احراز هویت، ورود چهار بازیکن، جریان SSE، پاس دادن کارت‌ها، شروع مرحله بازی، بازی یک کارت مجاز، بازگشت بازیکن به صندلی ربات، محرمانگی شناسه‌ها و رد ثبت نتیجه آنلاین جعلی را بررسی می‌کند.

## امنیت و تنظیمات

- `SESSION_SECRET` را در SnapDeploy به یک مقدار تصادفی طولانی و ثابت تنظیم کنید؛ در غیر این صورت توکن‌ها بعد از ری‌استارت معتبر نخواهند بود.
- `TRUST_PROXY` به‌صورت پیش‌فرض خاموش است. فقط اگر پروکسی مورد اعتماد شما هدر `X-Forwarded-For` را بازنویسی می‌کند، آن را روی `1` بگذارید.
- مهلت نوبت انسانی با `TURN_TIMEOUT_MS` تنظیم می‌شود و به بازه ۳۰ تا ۹۰ ثانیه محدود است.
