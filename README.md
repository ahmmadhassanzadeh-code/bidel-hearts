# بیدل — نسخه ارتقایافته

بیدل یک بازی آنلاین چهار نفره Hearts با SSE، بازی فوری با ربات، امتیازشمار پاسور واقعی، پروفایل، رتبه‌بندی و چت اتاق است.

## اجرا

```bash
npm install
npm start
```

بدون `DATABASE_URL` سرور اجرا می‌شود، اما آمار و پروفایل فقط در حافظه همان اجرای سرور هستند و دائمی محسوب نمی‌شوند.

## PostgreSQL

برای فعال شدن ذخیره دائمی:

1. یک PostgreSQL بسازید.
2. مقدار `DATABASE_URL` را در محیط اجرای SnapDeploy قرار دهید.
3. برنامه را Deploy/Restart کنید.
4. سرور در اولین اجرا جدول‌های `bidel_players` و `bidel_events` را خودکار می‌سازد.

در صورت وجود `bidel-stats.json` قدیمی و فعال بودن دیتابیس، آمار قدیمی به‌صورت best-effort مهاجرت می‌شود. چون نسخه قدیمی آمار را با نام ذخیره می‌کرد، اتصال قطعی آن رکوردها به شناسه‌های جدید بازیکنان ممکن نیست؛ برای همین رکوردهای مهاجرتی با شناسه legacy نگهداری می‌شوند.

## قوانین ثبت آمار

- فقط بازی کامل انسانی چهار نفره ثبت می‌شود.
- حضور حتی یک ربات در طول بازی، کل بازی را از آمار حذف می‌کند.
- پایان توافقی ثبت نمی‌شود.
- بازی ناقص ثبت نمی‌شود.
- ثبت نتیجه با `event_id` یکتا و تراکنش PostgreSQL idempotent است.
- نتیجه بازی آنلاین در سرور محاسبه و ثبت می‌شود؛ مرورگر نتیجه را به سرور تحمیل نمی‌کند.

## استقرار روی SnapDeploy

- Repository را در GitHub قرار دهید.
- سرویس Node.js را به Repository وصل کنید.
- Build/Install: `npm install`
- Start: `npm start`
- Environment: `DATABASE_URL` و `SESSION_SECRET`
- بعد از Deploy، `/api/health` باید `{"ok":true,"db":true}` برگرداند.

## PWA

Service Worker فقط shell صفحات را cache می‌کند و API/SSE را cache نمی‌کند. برای هر نسخه جدید `CACHE_NAME` در `sw.js` افزایش داده می‌شود.
